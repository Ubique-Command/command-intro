# IT사역팀 소개 페이지 PRD

## 목적

IT사역팀의 비전, 목적, 팀원 구성을 소개하는 웹사이트의 초기 버전을 구축한다. 첫 단계에서는 팀 소개와 팀원 탐색이 가능한 정적 페이지 구조를 마련해 이후 실제 콘텐츠, 디자인 고도화, CMS 또는 DB 연동으로 확장할 수 있는 기반을 만든다.

## 배경

- 팀의 역할과 방향성을 외부 또는 내부 구성원에게 명확히 전달할 필요가 있다.
- 팀원 정보를 목록과 상세 페이지로 나눠 제공하면 탐색성이 좋아진다.
- 초기에는 더미 데이터로 구현하고, 이후 데이터 소스 교체가 쉬운 구조를 우선한다.
- 비전공자인 팀원도 에이전트를 사용해 자기 소개 페이지를 직접 수정할 수 있어야 한다.

## 범위

### 포함

- Next.js App Router 기반 프로젝트 초기 설정
- `src/` 디렉토리 기반 구조 정리
- 랜딩 페이지 `/`
- 팀원 목록 페이지 `/members`
- 팀원 상세 페이지 `/members/[name]`
- 더미 팀원 데이터 3~5명 구성
- 팀원별 개별 소개 페이지 파일 구조
- `docs/prd.md`, `docs/architecture.md` 초안 작성

### 제외

- 실제 운영 콘텐츠 확정
- 정교한 브랜딩 디자인
- 애니메이션
- CMS, DB, 인증, 관리자 기능
- 배포 실행 자체

## 사용자 시나리오

1. 사용자는 랜딩 페이지에서 IT사역팀의 비전과 목적을 확인한다.
2. 사용자는 팀원 소개 버튼을 통해 팀원 목록 페이지로 이동한다.
3. 사용자는 카드 그리드에서 특정 팀원을 선택한다.
4. 사용자는 상세 페이지에서 해당 팀원의 역할, 소개, 연락처성 정보, 강점을 확인한다.
5. 팀원은 자신의 소개 페이지 파일만 수정해 상세 콘텐츠를 관리한다.

## 요구사항

### 기능 요구사항

- 랜딩 페이지는 팀 소개 문구와 팀원 페이지 이동 요소를 포함해야 한다.
- 팀원 목록은 카드 그리드 형태여야 하며 반응형이어야 한다.
- 각 카드는 이름, 직책/역할, 프로필 이미지를 보여줘야 한다.
- 카드 클릭 시 상세 페이지로 이동해야 한다.
- 상세 페이지는 이름 기반 라우팅을 지원해야 한다.
- 한글 이름 URL 사용 시 디코딩 후 데이터와 매칭해야 한다.
- 목록 페이지로 돌아가는 링크가 있어야 한다.
- `app/members/[name]`는 라우팅만 담당하고 실제 소개 내용은 팀원별 개별 파일에서 렌더링할 수 있어야 한다.

### 데이터 요구사항

- 팀원 데이터는 `src/data/members.ts`에 둔다.
- 타입 정의는 `src/types/member.ts`에 분리한다.
- 추후 실제 데이터 소스로 교체하기 쉽도록 타입과 데이터 접근 경계를 분리한다.
- 팀원별 상세 콘텐츠는 별도 파일로 분리해, 비전공자도 자신의 파일만 수정하면 되도록 한다.

## 우선순위

1. 프로젝트 생성과 실행 가능 상태 확보
2. 라우팅 구조와 기본 UI 구현
3. 타입/데이터 분리
4. 팀원별 개별 소개 페이지 구조
5. 문서화

## 검증 기준

- `npm run lint`가 통과해야 한다.
- `/`, `/members`, `/members/[name]` 경로가 모두 렌더링되어야 한다.
- 모바일과 데스크탑에서 레이아웃이 깨지지 않아야 한다.
- `/members/홍길동` 같은 한글 경로 접근 시 정상적으로 상세 페이지가 열려야 한다.
- 팀원 상세 내용이 `app` 라우트 파일이 아니라 팀원별 개별 파일에서 렌더링되어야 한다.

## 향후 확장 메모

- 이름 중복 가능성이 생기면 `slug`를 필수 필드로 승격해 라우팅 식별자로 사용한다.
- 추후 CMS나 DB를 연결할 때도 상세 페이지 경로는 `slug` 기준으로 고정하는 편이 안전하다.
- Next.js의 `src/pages`는 Pages Router로 해석되므로, 작업용 디렉토리는 `src/member-pages`처럼 별도 이름을 사용하는 편이 안전하다.
